# 复盘工作流

## 触发

项目结束或失败后要复盘：为什么成功/失败、下次怎么改，而不是找替罪羊。

## 输入

- 必须：目标、结果、时间线。
- 最好有：决策记录、数据、参与者视角。

## 步骤

1. **事实时间线**：只写“发生了什么”，不写“谁错了”。区分事实 / 解释 / 归因。

2. **亚里士多德：目的与四因**（读 `../references/aristotle.md`）
   - 当初的 telos 是什么？结果与目的差在哪？
   - 四因各缺什么：质料（资源）、形式（结构）、动力（推动）、目的（方向）。

3. **黑格尔：矛盾与扬弃**（读 `../references/hegel.md`）
   - 当时每个决策各自的“真理环节”是什么？
   - 哪些原则推到极端后自我瓦解？矛盾何时显形？
   - 这次失败取消了什么、保留了什么、下次要提升到什么？

4. **维特根斯坦：概念漂移**（读 `../references/wittgenstein.md`）
   - 团队在用的关键概念（“完成”“质量”“上线”）是否漂移了？
   - 复盘时是否在混用不同的语言游戏？

5. **写教训**：把教训写成“可操作的规则 + 它的适用边界”，不要写成口号。

6. **成文**：填充 `../templates/council-report.md`。

## 产出

`../templates/council-report.md`

## 质量门

- [ ] 事实、解释、归因分层，没有把解释当事实。
- [ ] 每条教训可执行、有适用边界，不是“下次多沟通”。
- [ ] 指出系统/结构问题，不把失败全归为个人。
- [ ] 给出了下一次的验证信号。
